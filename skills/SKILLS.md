# Skills index

One skill per verb. Load the skill you need when you need it; they are deliberately independent so each
can improve without touching the others. `study-session` is the frame the others run inside.

| Skill | Use it when | The guard that matters most |
|---|---|---|
| [`study-session`](study-session/SKILL.md) | Opening, running and closing a study block | Never start what cannot be finished in the block |
| [`read-along`](read-along/SKILL.md) | Delivering reading units as speech with a synced highlight | One page at a time; the EXPECT slug check before any mark |
| [`take-notes`](take-notes/SKILL.md) | Writing anything into `learner/notes/` | Notes are private and never leave the machine |
| [`research-summarise`](research-summarise/SKILL.md) | Gathering and condensing material for the learner | Verify against a second source; summarise at the learner's register |
| [`make-reflections`](make-reflections/SKILL.md) | Writing reflections and short personal answers | Three bullets maximum, two is better |
| [`run-labs`](run-labs/SKILL.md) | Interactive lab sessions | Learner led; hold the submission for a go-ahead |
| [`make-submissions`](make-submissions/SKILL.md) | Uploading work to the learning portal | Nothing is submitted without the learner's explicit, post-read go-ahead |

## How they compose

```
Discover:  study-session -> read-along -> take-notes        (per unit, in that order)
Practise:  study-session -> run-labs, research-summarise
Apply:     study-session -> research-summarise -> make-reflections -> make-submissions
```

The loop inside every delivery is always: listen, retrieve, explain, write notes, then mark. A skill
never redefines the loop; it only covers its own step.

## Changing a skill

When a block teaches something that would have cost time to rediscover, fold it into the relevant
skill the same day and date it. If it corrects something the skill says, fix it where it is wrong
rather than appending a contradiction. A stale skill is worse than no skill.
